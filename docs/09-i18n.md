# 09 — Internacionalización (i18n)

Fundación multi-idioma para escalar a mercados internacionales. Stack:
**i18next + react-i18next + i18next-browser-languagedetector**.

## Cómo funciona

- Config: [`src/i18n/index.js`](../src/i18n/index.js). Inicializado en [`main.jsx`](../src/main.jsx).
- Idiomas: **es** (default + fallback, cobertura 100%), **en**, **pt**.
  Locales en `src/i18n/locales/{es,en,pt}.json`.
- **Auto-detección**: el detector elige el idioma según el navegador en la primera
  visita y lo cachea en `localStorage` (`app-lang`). `nonExplicitSupportedLngs`
  mapea `es-AR → es`, `pt-BR → pt`, `en-US → en`.
- **`<html lang>`** se sincroniza solo con el idioma activo (a11y + SEO).
- **Fallback seguro**: si falta una clave, i18next devuelve el texto en `es`
  (o la clave). Nunca crashea — degradación elegante.
- Selector de idioma: [`src/components/LanguageSwitcher.jsx`](../src/components/LanguageSwitcher.jsx),
  ubicado en **Configuración** (siempre accesible). Como hay auto-detección, no es
  imprescindible un switcher pre-login.

## Uso en componentes

```jsx
import { useTranslation } from 'react-i18next';

function Foo() {
  const { t } = useTranslation();
  return <h1>{t('section.calc')}</h1>;            // texto simple
  // interpolación: t('welcome.greeting', { name }) → "Bienvenido Nacho"
}
```

En **class components** (ej. `ErrorBoundary`) se usa la instancia directa:
`import i18n from '../../i18n/index.js'` → `i18n.t('errors.retry')`.

## Qué está migrado (chrome)

✅ Navegación/sidebar (`AppShell`), pantalla de bienvenida, `ErrorBoundary`,
`PlanHub` (billing), `Settings`, `LanguageSwitcher`, `Loader`.

## Qué falta migrar (incremental, NO bloquea)

Las herramientas profundas siguen en español y se migran de a una:
`Calculator`, `ContainerLoader`, `PalletBuilder`, `Comparator`, `NcmSearch`,
`Simulator`, `Prices`, `Products`, `LoginPage`, `ProfilePanel` (dentro de AppShell),
y los export PDF. **Los motores no llevan strings de UC**, así que su migración no
los toca. El default `es` hace que estas vistas se vean igual que siempre.

## Agregar un idioma

1. Crear `src/i18n/locales/<code>.json` copiando la estructura de `es.json`.
2. Importarlo y registrarlo en `src/i18n/index.js` (`resources`, `supportedLngs`)
   y en `SUPPORTED_LANGS`.
3. `npm test` — el test de paridad ([`i18n.test.js`](../src/__tests__/i18n.test.js))
   exige **las mismas claves, sin vacíos y con los mismos `{{placeholders}}`** en
   todos los idiomas. Si falta una clave, el test falla.

## Migrar un componente

1. `const { t } = useTranslation();`
2. Reemplazar strings literales por `t('namespace.key')`.
3. Agregar la clave en los **3** locales (es/en/pt) — el test de paridad lo exige.
4. Interpolaciones con `{{var}}` deben existir en los 3 idiomas.

## Notas de localización pendientes

- **Moneda/números**: `formatters.js` usa `es-AR` fijo. Para multi-moneda real
  habría que parametrizar el locale (y, a futuro, el TC/моneda del negocio). Es una
  mejora aparte que **toca `calcCostos`/datos**, fuera del alcance actual.
- Las fechas en `Settings` ya usan el locale activo (`i18n.language`).
